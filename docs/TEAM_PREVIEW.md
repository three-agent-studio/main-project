# Общий просмотр сайта с Mac

Адрес командного просмотра: [three-agents-studio.serveousercontent.com](https://three-agents-studio.serveousercontent.com/). Он работает, пока на Mac запущены PostgreSQL и launcher с зарегистрированным ключом и этим hostname.

Этот режим публикует собранный интерфейс и Django API через временный HTTPS-туннель Serveo или localhost.run. Участникам не нужно подключаться к Wi-Fi владельца Mac. Оплачивать сервер, открывать входящие порты роутера и менять DuckDNS не требуется.

Это публичный адрес: личный кабинет по-прежнему требует входа. Используйте только вымышленные данные согласно README. Админка в этом режиме отвечает 404. SSH и HTTPS шифруют соединения; выбранный провайдер завершает TLS на своей стороне. Это внешний провайдер трафика, не собственный сервер проекта.

## Подготовка

Работайте в отдельном checkout/worktree той версии, которую команда должна видеть. Локальная разработка в другой папке может продолжаться независимо. Нужны Python 3.12+, Node.js 22, OpenSSH и запущенный PostgreSQL (см. docs/DEVELOPMENT.md).

Из корня выбранного checkout:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cd frontend
npm ci
npm run build
cd ..
```

В корневом `.env` должны находиться POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_HOST и POSTGRES_PORT. Можно передать путь к существующему `.env` из другого checkout. Значения разбираются как строки с shell-кавычками, файл не исполняется. Пароли с пробелами или `#` заключайте в кавычки. Файл и созданная папка `.team-preview` исключены из Git.

Перед применением новых миграций сделайте резервную копию БД. Launcher намеренно не применяет миграции автоматически. Применить их один раз можно с известным HTTPS origin через `scripts/team_preview.py --origin https://example.lhr.life --migrate`; после завершения миграций и запуска Gunicorn остановите команду Ctrl+C. Обычный запуск ниже проверяет отсутствие неприменённых миграций.

## Запуск

```sh
.venv/bin/python scripts/share_preview.py --provider serveo --database-env .env
```

Выбор транспорта задаётся `--provider serveo` или `--provider localhost-run` (по умолчанию localhost-run). Приложение и правила доступа от этого не меняются. При медленной загрузке через localhost.run проверьте Serveo: у бесплатного localhost.run есть ограничение скорости, и даже сжатый большой JS может загружаться долго. Доступность каждого провайдера через мобильную сеть проверяется отдельно.

У бесплатного Serveo перед сайтом может появиться собственное предупреждение со ссылкой перехода. Это страница провайдера, отдельная от приложения. Предупреждения самого браузера о недоверенном сертификате обходить нельзя.

Оставьте этот Терминал открытым. После строки `Team preview: https://…` дождитесь `Booting worker`, откройте ссылку в браузере и передайте её участникам. Для проверки личного кабинета используйте уже созданные демонстрационные аккаунты; пароль не отправляйте в GitHub Issues/PR.

Скрипт поднимает Gunicorn только на `127.0.0.1:19090`, разрешает конкретный домен для Django/CSRF и включает secure cookies. Перед запуском launcher создаёт gzip-варианты frontend-файлов; файлы Vite с хешем в имени кешируются как immutable, HTML остаётся no-store. WhiteNoise согласует Content-Encoding с браузером, уменьшая объём загрузки через медленный туннель. WhiteNoise отдаёт только собранный `frontend/dist` и собранную Django-статику. Исходники, `.env`, база данных и Vite dev server не публикуются. DEBUG отключён. Секрет сессии сохраняется локально с правами 600, чтобы перезапуск не сбрасывал сессии на прежнем домене.

Mac должен оставаться включённым, подключённым к интернету и с открытой крышкой. На macOS скрипт использует `caffeinate`, чтобы предотвратить обычный сон от бездействия; закрытая крышка и выключение всё равно прервут доступ. PostgreSQL/Docker тоже должен работать. Остановить сайт и туннель — Ctrl+C в этом Терминале.

Бесплатный провайдер может завершить срок действия туннеля, даже если Mac продолжает работать. В этом случае скрипт сохраняет Gunicorn запущенным и автоматически повторяет SSH-подключение с задержкой. Если домен прежний, сервер не перезапускается, текущие сессии сохраняются. Если провайдер выдал другой домен, скрипт перезапускает свой сервер с новым host/CSRF origin и выводит новую ссылку — её нужно заново передать участникам. Временный URL не является гарантированно постоянным адресом.

Ошибки авторизации, параметров SSH и проверки host key останавливают запуск сразу. Временные ошибки сети/DNS по умолчанию повторяются до восстановления соединения или Ctrl+C; задержки растут до 30 секунд. Это позволяет пережить длительную потерю сети и пробуждение Mac без ручного перезапуска. При необходимости задайте конечный предел флагом `--max-connection-failures 5`; значение по умолчанию `0` означает отсутствие такого предела. Ctrl+C завершает сервер и туннель, дальнейшего переподключения нет. Mac, PostgreSQL и Терминал должны продолжать работать.

Актуальный адрес и состояние соединения сохраняются атомарно в игнорируемом `.team-preview/status.json`. `tunnel_connected` означает выданный SSH-туннель; готовность приложения подтверждается загрузкой страницы и входом. `reconnecting` означает временную недоступность ссылки, `failed` — необходимость прочитать `.team-preview/tunnel.log`, `stopped` — ручную остановку. Не передавайте участникам прежнюю ссылку, пока статус не стал `tunnel_connected`. При зависшей в браузере загрузке после восстановления обновите страницу.

Для адреса, который участники смогут сохранить и открывать после переподключений, используйте зарезервированный hostname и SSH-ключ своего аккаунта. Текущий DuckDNS-домен этим скриптом не используется.

## Закреплённый адрес Serveo

Войдите в [консоль Serveo](https://console.serveo.net/), добавьте публичный ключ проекта и зарезервируйте доступное имя в своём аккаунте. Используйте отдельный ключ для этого проекта, не ключ от GitHub. Если ключ ещё не создан, из корня checkout один раз выполните:

```sh
mkdir -p .team-preview
chmod 700 .team-preview
ssh-keygen -t ed25519 -N '' -C deanery-team-preview -f .team-preview/serveo_ed25519
cat .team-preview/serveo_ed25519.pub
```

В консоль добавляется только строка из `.pub`. Приватный файл без `.pub` хранится локально с правами 600 в игнорируемой папке. Пустая passphrase нужна для автоматического SSH-переподключения; ключ предназначен только для этого туннеля и не даёт доступа к проектной БД или GitHub.

Запускайте с полным именем, фактически выданным консолью (ниже пример):

```sh
.venv/bin/python scripts/share_preview.py --provider serveo --database-env .env --identity-file .team-preview/serveo_ed25519 --hostname three-agents-studio.serveousercontent.com
```

Скрипт использует только этот ключ, запрашивает указанный hostname и останавливается при выдаче другого имени. Он не переключает зарегистрированный адрес на случайный домен. Наличие параметра `--hostname` не резервирует имя само по себе: оно должно принадлежать вашему аккаунту и быть разрешено для добавленного ключа.

## Проверка из другой сети

1. На iPhone выключите Wi-Fi и откройте HTTPS-ссылку через мобильный интернет без VPN.
2. Проверьте главную страницу, `/profile`, вход и отображение своего профиля.
3. В приватном окне `/api/v1/me/` должен вернуть 403, `/admin/`, `/.env` и отсутствующий `/assets/missing.js` — 404.
4. Попросите второго участника повторить проверку у своего оператора. Доступность из всех сетей России заранее не гарантируется: это нужно проверить на реальных подключениях.

## Как показывать новые изменения

Запущенная версия — снимок собранного checkout. Изменения из других веток не появляются на сайте автоматически: их нужно сначала проверить и объединить в ветку просмотра. Не переключайте ветку и не меняйте сборку в работающей папке.

Остановите просмотр Ctrl+C, обновите выбранный checkout, установите изменившиеся зависимости, примените необходимые миграции после резервной копии, повторите `npm run build` в `frontend` и запустите просмотр снова. Разработка в другой папке в это время может продолжаться. Это обновление с короткой остановкой; непрерывные автоматические deployments относятся к отдельной задаче хостинга #11.

Если SSH не подключается, скрипт печатает ошибку. Проверьте интернет и доступность выбранного провайдера из обычного Терминала. Не отключайте проверку SSH host key или HTTPS-сертификата для обхода ошибок.

Документация [Serveo](https://serveo.net/docs/) и localhost.run: [HTTPS и proxy headers](https://localhost.run/docs/http-tunnels), [временные URL и nokey](https://localhost.run/docs/faq), [граница TLS](https://localhost.run/docs/security).

## Диагностика пустой или медленной страницы

В другой вкладке Терминала из корня checkout выполните:

```sh
.venv/bin/python scripts/check_preview.py https://YOUR-CURRENT-HOST.lhr.life
```

Скрипт использует системный curl с обычной проверкой TLS и поддержкой сжатия. Он сравнивает HTML/JS/CSS публичного адреса с локальной сборкой, выводит число переданных байтов и время и сохраняет отчёт в игнорируемой папке `.team-preview/asset-check.json`. Cookies и учётные данные не используются. `matches_build: true` означает полное совпадение после распаковки; тайм-аут или неполный JS может оставить React без возможности запуститься. Если URL уже сменился, используйте актуальный адрес из Терминала с просмотром.

CI отдельно проверяет собранный frontend через Gunicorn в Chromium и WebKit, включая gzip и переход/прямую загрузку страницы профиля. Vite dev server в этой проверке не участвует.

### SSH-аутентификация Serveo

Launcher предлагает выделенный публичный ключ, затем допускает `keyboard-interactive`, который Serveo может использовать для завершения входа. Принудительные `PreferredAuthentications=publickey` и `BatchMode=yes` в проверенном окружении приводили к Permission denied даже при совпадающем ключе в консоли. Это не меняет проверку SSH host key, ограничение конкретного hostname или авторизацию Django.

Для диагностики добавьте `--ssh-verbose` к обычной команде запуска. Подробности сохраняются только в локальном `.team-preview/tunnel.log`. Для регулярного запуска этот флаг не обязателен.
