# LEARNING.md — Память и уроки проекта

Этот файл помогает Codex учитывать **подтверждённый опыт предыдущих сессий**. Он относится только к текущему проекту.

**Правила ведения:**
- Читать в начале работы над проектом (см. `AGENTS.md`).
- Добавлять выводы только после реально выполненной задачи, проверки или явной корректировки пользователя.
- Записывать кратко: **контекст → правило/вывод → подтверждение**.
- Избегать повторов, устаревших записей, паролей, токенов и персональных данных.
- Если урок перестал быть актуальным, исправить или удалить запись с пояснением причины.
- Если подтверждённых уроков ещё нет, оставлять этот файл почти пустым.

### 2026-11-06 — Основа приложения и параллельная работа
- Контекст: в предыдущей сессии создан каркас и распределены задачи трём участникам.
- Правило: №1 владеет backend/accounts, core, config и контрактами; №2 — общими UI и студенческими разделами; №3 — заявками, уведомлениями, кабинетом сотрудника и инфраструктурой. Новые страницы подключать через app/modules.ts.
- Подтверждение: PR #14, Issues #2–#13, docs/DEVELOPMENT.md.

### 2026-11-06 — Сессии, зависимости и проверки
- Контекст: каркас проверен в GitHub Actions на PostgreSQL, Chromium desktop и ширине 360 px.
- Правило: сохранять один origin для интерфейса/API, использовать серверные сессии и CSRF, проверять владельца данных на сервере. Зависимости устанавливать через npm ci и Python constraints.
- Подтверждение: успешный CI 42088478683 — 5 серверных, 3 frontend-теста и 2 браузерных сценария. Chromium с узким viewport не подтверждает совместимость с Safari/iPhone.

### 2026-11-06 — Демонстрационные пользователи

### 2026-11-06 — Адрес для проверки с телефона
- Контекст: при проверке с iPhone использовался URL с 127.0.0.1, а Vite слушал только loopback Mac.
- Правило: на другом устройстве открывать LAN-IP Mac, запускать frontend через dev:lan и явно разрешать этот IP в Django development settings. Backend можно оставить на loopback за Vite proxy.
- Подтверждение: адрес предоставлен пользователем; исходные package.json и ALLOWED_HOSTS проверены. Физический iPhone ещё требует повторной проверки с верным адресом.

### 2026-11-13 — Просмотр интерфейса на Windows без Docker
- Контекст: у №3 Windows без Docker и PostgreSQL, а для редизайна нужно видеть вход, главную и профиль с данными.
- Правило: держать отдельный settings-модуль вне репозитория (`from config.settings.development import *` + SQLite-файл), подключать через `PYTHONPATH` и `DJANGO_SETTINGS_MODULE`, выполнить `migrate` и `tests/seed_browser.py` (студенты, преподаватель, инженерное расписание), затем `runserver` (без `--noreload`, иначе шаблоны кешируются) + `npm run dev`. В репозиторий не коммитить, production по-прежнему только PostgreSQL. На Windows и без изменений падают: 5 тестов `test_preview_launcher.py` (ssh/`nul`/select), 2 теста `test_teacher_provisioning.py` (chmod 0600) и SHA-проверка `npm run test:security` (git с `core.autocrlf=true` переводит `frontend/vendor/picomatch` в CRLF). Это не регрессии; на Linux CI они проходят.
- Подтверждение: ветки `design/warm-ui` и `design/swiss-ui`; экраны проверены на 360 и 1280 px; остальные backend-тесты проходят.

### 2026-11-13 — Дизайн-токены живут в двух местах
- Контекст: страница входа рендерится Django и не может импортировать `frontend/src/shared/styles/tokens.css`.
- Правило: при смене палитры или шрифта менять и `tokens.css`, и `:root` в `backend/core/static/core/auth/auth.css`. Шрифт (с 2026-11-20 — Inter) хранится в проекте: npm `@fontsource-variable/inter` для React, копия woff2 + `OFL.txt` в `core/static/core/fonts/` для входа, без внешних CDN. Цвета рамок полей и кнопок — `--line-control` (≥3:1), а `--line-strong`/`--line` только декоративные. Статусы показывать через `shared/ui/Badge` словами, цвет лишь дублирует смысл.
- Подтверждение: расчёт контраста WCAG для всех пар палитры в ветках `design/warm-ui` и `design/swiss-ui`.
